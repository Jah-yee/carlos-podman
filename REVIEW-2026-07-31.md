## Findings

Severity reflects impact on the *production* (Ansible-provisioned) path.
Line numbers are for commit `2266746`. Every finding below was verified
directly against the code (and where possible reproduced live); none are
speculative.

### High

**H1. `rotate age-key` can destroy the only copy of the new master key
mid-rotation** — `carlos_ctl/secrets.py:1874-1879`. The re-keyed bundle is
committed (`os.replace(new_bundle, s.secrets_bundle)`) *before* the new
private key is persisted to `age_key_file`; the `finally` unlinks the `/run`
tmpfs copy. A crash/ENOSPC/EROFS in that window leaves the live bundle
decryptable only by a key that no longer exists anywhere on the host —
recovery requires the off-host escrow *plus* a pre-rotation bundle from
backups. Every other secrets path here does persist-before-destroy
(`_seal_one`, `_maybe_write_recovery_wrap`, `_rotate_restic`); this is the
one gap. Fix: write + chmod the new key (and pub) files *before* swapping
the bundle in.

**H2. `carlos-ctl alert`'s OnFailure throttle state is wiped by every
monitor run, re-creating the page flood the throttle exists to prevent** —
`carlos_ctl/monitor.py:126-135` + `carlos_ctl/alert.py:127-146`.
`recovery_sweep()` unlinks every state file not in `m.fired`; `cmd_alert`'s
`onfailure-*` stamps live in the same directory and are never in `m.fired`
(the monitor's own key for a failing unit is `failed-unit-*`). While a unit
is *still failing*, each monitor pass deletes the stamp, so the next failure
re-pages — the effective throttle window collapses from
`ALERT_REMIND_HOURS` (24 h) to the monitor interval. A restic outage
overnight pages every backup-timer interval. alert.py's own docstring
describes the sweep as re-arming "a recovered unit", but the sweep cannot
tell recovered from still-failing for state it does not own. Fix: exempt the
`onfailure-` prefix from the sweep (cmd_alert already self-expires), or give
cmd_alert its own state dir.

### Medium

**M1. `--instance` is not fully authoritative: the selected instance's own
`carlos-app.env` can silently re-point `EMR_HOME`** — `carlos_ctl/cli.py:249-252`
vs `carlos_ctl/config.py:387`. The selector sets `os.environ["EMR_HOME"]`
and pops `ENV_FILE`, but `Settings` gives the *file's* `EMR_HOME` precedence
over the environment. An env file carrying a stale/copied `EMR_HOME=<other
instance>` line redirects every mutating verb — including the lock and the
`.deployed`/guard markers — at the other instance's home, the exact
wrong-instance footgun the `==> target:` banner exists to prevent (the
banner does print the resolved home, the one mitigation). Fix: after
`--instance`, force `EMR_HOME` from the registry over the file value (or
refuse on mismatch).

**M2. Restore proceeds into the destructive load after a *failed* final
binlog ship** — `carlos_ctl/backup.py:1904-1912`. On a restore-to-latest,
if the final ship fails (repo backend down), the code only warns, then
drops and reloads the live DB and replays the stale chain — silently
discarding up to one ship interval of committed writes, at a point where
refusing would still have been free. Every comparable loss path requires an
explicit `CARLOS_*=1` ack; this one should too.

**M3. `--stop-datetime` restores never ship local binlogs and never check
whether the target predates the last ship** — `carlos_ctl/backup.py:1629-1652,1780`.
A PITR target *after* the last 15-min ship but covered only by the unshipped
active binlog replays short and reports success with no warning.

**M4. Boot-time reap of cleartext credential drop-files is a silent no-op** —
`carlos_ctl/secrets.py:805` (`ReadOnlyPaths={emr_home}` in the secrets unit)
vs `reap_credential_dropfiles` (125-144), which writes/unlinks under
EMR_HOME and suppresses the resulting EROFS. After a headless rotation, the
`.new-*` cleartext credential files persist on disk across reboots until a
manual `seal`, while every render reports success.

**M5. Half-placed operator cert is clobbered in selfsigned mode** —
`carlos_ctl/tlsops.py:77-103`. `ensure_selfsigned_cert` only protects when
*both* PEMs exist; `fullchain.pem` present + `privkey.pem` not yet copied →
the next `play` regenerates over the operator's fullchain. A one-file state
should refuse loudly. (Related low: the self-issued CN check at :66 is a
substring match, and an empty `SERVER_NAME` matches any CN.)

**M6. `carlos-ctl setup`'s printed NEXT STEPS reference the retired schema
build** — `carlos_ctl/setup.py:311-318` tells the operator to load
`oscarinit.sql` / `oscarinit_2025.sql` / `oscardata.sql` /
`oscarinit_{on,bc}.sql`, which upstream retired for the Flyway
`migration/{common,on,bc}/V1…` files — the wizard's own README/QUICKSTART
document the correct list. It also omits the `DEFAULT CHARACTER SET utf8mb4`
clause on CREATE DATABASE. A fresh install following the wizard fails (or
worse, resurrects legacy SQL from git history).

**M7. `dev-setup.sh` violates its own off-argv contract** —
`scripts/dev-setup.sh:132-142`. The DB password, the app encryption key, and
the password hash all ride `sed`/`python`-argv (`-e "s@…@$DB_PW@"`), visible
in `/proc/*/cmdline` for the render's duration, while the header and
QUICKSTART promise "never argv". (The hash step at :160 correctly uses
stdin.) Also: `&` is missing from the blocked-charset gate (sed expands it
to the matched pattern), and the Jinja-leftover failure handler greps the
rendered file to stderr, which can echo `db_password=` fragments into CI
logs. Verified live: the render works, but `ps` during it shows the secret.

**M8. Monitor/alert curl `-K -` config values are never escaped for the
curl config format** — `carlos_ctl/alert.py:68`,
`carlos_ctl/obsquery.py:36-44`, `carlos_ctl/monitor.py:947-949`. A webhook
URL / obs password containing `"` or `\` (legal via the env parser's
ANSI-C quoting) corrupts the generated config; a newline injects arbitrary
curl directives (root context). Files carrying these values are root-0600,
so this is defense-in-depth + correctness, not a live escalation. Same class:
`_rotate_obs_http`'s operator-supplied `OBS_HTTP_NEW_PASSWORD`
(`secrets.py:1989-1998`) and the role's `journald-collector.toml.j2:97-99`
TOML render — no charset assert anywhere on the obs credential family,
unlike the db password and encryption key which are asserted.

**M9. Chain-identity sidecar written mode-umask, breaking subsequent binlog
ships under umask 077** — `carlos_ctl/backup.py:599-606`. `.carlos-server-identity`
is `write_text()` with no chmod (unlike `.repo-posture` at :168-177, which
chmods 0644 for exactly this reason). One manual root `backup binlogs` from
a umask-077 shell creates it 0600; the rootless restic container can then
never read it and **every subsequent ship fails** until a manual chmod.

### Portability / docs (found by executing the documented paths)

**P1. Control-node bootstrap breaks on current bcrypt** — README's
`pip install ansible-core passlib netaddr` on a 2026 machine installs
bcrypt ≥ 4.1 (5.0 here), which passlib 1.7.4 cannot drive:
`password_hash('bcrypt')` fails (`error reading bcrypt version`, then the
72-byte error from passlib's own probe) — the Caddyfile render task dies and
`tests/ansible-checks.sh` fails the same way. Verified: pinning
`bcrypt==4.0.1` turns the whole check suite green with zero repo changes.
The role should either pin/document `bcrypt<4.1` on the control node, or
hash with `bcrypt_hash()` in a filter that doesn't route through passlib.

**P2. The QUICKSTART Playwright instruction can't reach 14/14 with the
stock script over https** — the app repo's
`scripts/login-playwright-checks.js` sets `ignoreHTTPSErrors` on the
*browser* context only; its three `request.newContext()` API contexts
(lines 289/315/488) reject the in-pod self-signed cert (which also has no
`127.0.0.1` SAN), so `BASE_URL=https://127.0.0.1:8443/carlos` yields 11/14.
With those three calls patched to `{ ignoreHTTPSErrors: true }`: 14/14 PASS.
Fix belongs in the app repo (or QUICKSTART should mention the caveat and
the socket/`MYSQL_HOST` incantation — note `MYSQL_UNIX_PORT` is *not*
honored by the mariadb client; a socket symlink or `MYSQL_HOST` pointing at
a TCP-published dev alternative is needed).

**P3. Fresh-install schema race wedges the app until a restart** — followed
QUICKSTART order exactly (`kube play`, then load schema): on a fast host
Tomcat reached Spring init seconds before `CREATE DATABASE oscar` landed;
the webapp context hard-fails (`Unknown database 'oscar'`) and serves 404
permanently — the liveness probe does eventually restart it (~6-8 min), but
the QUICKSTART should say "if the app booted before the schema existed,
`podman restart carlos-app-carlos`" (or the app pod's wait-for-db loop
should wait for the *database*, not just the TCP port). Verified: after a
manual restart the app came up clean and served the login page.

**P4. `make test`/tooling assumption** — `pytest` must run against the same
interpreter that has PyYAML/bcrypt; a `pipx`-style pytest on PATH fails
collection. Cosmetic (document `python3 -m pytest` in the Makefile if this
bites others).
